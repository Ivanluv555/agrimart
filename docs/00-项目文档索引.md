# 农惠达项目设计总览

设计阶段：开发起步阶段。系统规划为用户、农资买卖、支付三个独立业务微服务，配套统一网关、注册与配置中心。当前源码仍是待迁移原型，设计不代表已经部署或通过验收。

## 设计过程

先确定业务边界，再依次推导功能、技术、服务、调用、接口和数据；前一步产出作为下一步输入。各项设计应独立说明必要的责任、输入输出与约束。

| 步骤 | 设计主题 | 主要内容 |
| --- | --- | --- |
| 01 | 功能架构 | 用户层、Web 与后续移动端、模块、核心功能、特点和操作步骤 |
| 02 | 技术架构 | React + MUI、Flutter + Material、网关、三服务、独立库、注册配置与沙箱 |
| 03 | 服务划分 | 三服务的功能、数据、接口、非职责与独立部署边界 |
| 04 | 业务调用 | 串行与并行依赖、输入输出接力、幂等及故障恢复 |
| 05 | 接口定义 | 44 个外部操作与 10 个内部操作，共 54 个目标操作 |
| 06 | 数据设计 | 三库分区，字段、主外键、唯一键、基数及跨服务逻辑关联 |

## 客户端与设计体系

Web 客户端采用 React + TypeScript + MUI（Material UI），现有 Ant Design 原型逐步迁移。后续新增独立 Flutter 移动客户端，使用 Flutter 的 Material 组件体系；不是将手机浏览器页面作为移动 App。

两端遵循 Material 设计原则，统一主题色、字体层级、间距、交互反馈和可访问性，目标是提高易用性和一致性、降低上手成本。组件分别由 React 和 Flutter 实现，共享设计规范与业务契约。

## 三个业务微服务

| 编号 | 服务 | 应用 | 独立逻辑数据库 |
| --- | --- | --- | --- |
| S01 | 用户管理 | agrimart-user-service | agrimart_user |
| S02 | 农资买卖 | agrimart-trade-service | agrimart_trade |
| S03 | 支付 | agrimart-payment-service | agrimart_payment |

三个独立应用可以共用一个 MySQL 实例，但使用独立库与账号，不跨服务建外键、不跨库访问、不共享事务。统一网关、Nacos 注册与配置中心属于基础设施，不计为第四个业务服务。商品、库存、订单、人工物流、评价和退款审核统一在 S02 内完成。

## 工程与交付约束

- 独立验证三服务、网关、注册配置及跨服务业务异常。
- 目标工程具备清晰层次、服务内事务、持久化待办与独立数据库迁移。
- 数据库设计采用可编辑 ER 图；API 使用 OpenAPI 3.0.3，模型引用仅在同一契约内部解析。
- 设计说明独立表达，不通过其他文档的链接或交叉定位代替当前内容。
- Flutter 移动端为后续建设，尚未创建工程或交付页面；Web 的组件库迁移也不等于已经完成。

## 当前实现差距

当前后端仍为单体原型，已有用户、商品、订单、评价接口共 19 个，尚未完成三服务、可信业务令牌、三库隔离、网关、注册配置以及沙箱与退款执行。前端仍使用 Ant Design，MUI 和 Flutter 均为目标规划。前后端成功码、分页和评价字段也需统一。
