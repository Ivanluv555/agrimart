# 服务清单

本清单描述开发起步阶段将要实现的服务，逐项列出功能、职责、接口和数据边界。目标只包含三个业务微服务。

## 1. 部署单元与基础设施

| 类别 | 应用或设施 | 建议开发端口 | 责任 |
| --- | --- | --- | --- |
| 表现端 | agriapp | 5173 | React + MUI 的 Web 页面，覆盖农户、商家及管理员操作；现有 Ant Design 待迁移 |
| 后续表现端 | agrimart-mobile | 不适用 | Flutter 移动客户端，使用 Material 组件，复用统一网关和业务接口；工程待创建 |
| 入口设施 | agrimart-gateway | 8080 | 统一 /api 入口、路由、请求关联、身份预校验与内部路由隔离 |
| 业务服务 | S01 agrimart-user-service | 8081 | 用户、认证、角色与商家入驻 |
| 业务服务 | S02 agrimart-trade-service | 8082 | 农资买卖及履约 |
| 业务服务 | S03 agrimart-payment-service | 8083 | 沙箱资金执行与核对 |
| 治理设施 | Nacos | 按选定版本配置 | 三服务和网关的注册、发现及配置分发 |
| 数据设施 | MySQL | 按环境配置 | 三个独立业务逻辑库与独立账号 |

端口是设计默认值，不代表当前源码已启动这些进程。Nacos 管理端和各业务服务端口不直接向公网开放；配置中心的基础设施元数据不计入三个业务库。

## 2. 服务、功能与接口清单

| 服务 | 功能 | 功能描述 | 涉及接口（省略 /api） |
| --- | --- | --- | --- |
| S01 用户服务 | 用户与认证 | 注册、登录、退出、本人资料、可撤销令牌 | /users/register、/users/login、/users/logout、/users/me |
| S01 用户服务 | 商家准入 | 农户提交申请，管理员审批，申请和角色在同库事务更新 | /merchant-applications、/merchant-applications/me、/admin/merchant-applications、/admin/merchant-applications/{applicationId}/decision |
| S02 农资买卖服务 | 商品与库存 | 分类搜索、店铺、发布维护、上下架、库存流水、平台禁售 | /products、/products/{id}、/products/{id}/status、/products/{id}/stock、/merchant/products、/admin/products |
| S02 农资买卖服务 | 结算与订单 | 同库拆单和预留库存、本人购买及销售订单、取消与超时关闭 | /checkouts、/checkouts/{checkoutNo}、/orders/me、/orders/{id}、/merchant/orders、/orders/{id}/cancel |
| S02 农资买卖服务 | 人工物流 | 商家填写承运方与运单号、买家确认收货完成 | /merchant/orders/{id}/shipment、/orders/{id}/receipt |
| S02 农资买卖服务 | 退款业务 | 买家申请、商家审核、冻结发货、追踪执行结果投影 | /orders/{id}/refunds、/refunds/me、/refunds/{refundId}、/merchant/refunds、/merchant/refunds/{refundId}/decision、/merchant/refunds/{refundId}/retry |
| S02 农资买卖服务 | 评价 | 已完成订单逐项评价、商品均分、一次商家回复 | /reviews、/reviews/me、/reviews/product/{productId}、/merchant/reviews、/reviews/{id}/reply |

## 3. 内部服务接口

| 编号 | 提供方 | 方法与路径 | 调用方 | 功能 |
| --- | --- | --- | --- | --- |
| U01 | S01 | POST `/internal/auth/introspections` | gateway、S02、S03 | 校验用户令牌 |
| U02 | S01 | GET `/internal/merchants/{merchantId}` | S02 | 查询商家经营资格 |
| T01 | S02 | POST `/internal/orders/{orderId}/payment-authorizations` | S03 | 授权订单支付 |
| T02 | S02 | POST `/internal/orders/{orderId}/payment-events` | S03 | 归并可信支付或关单事实 |
| T03 | S02 | GET `/internal/refunds/{refundNo}/execution-authorization` | S03 | 读取退款执行授权 |
| T04 | S02 | POST `/internal/refunds/{refundNo}/execution-events` | S03 | 归并退款执行事实 |
| P01 | S03 | POST `/internal/payments/{paymentNo}/close` | S02 | 接受关闭支付命令 |
| P02 | S03 | POST `/internal/refunds` | S02 | 接受或重试全额退款执行 |
| P03 | S03 | GET `/internal/payments/{paymentNo}` | S02 | 查询权威支付状态 |
| P04 | S03 | GET `/internal/refunds/{refundNo}` | S02 | 查询权威退款执行状态 |

## 4. 数据与事务归属

- S01 仅管理用户、入驻申请、令牌会话与自己的幂等记录；商家资格通过 U02 提供给 S02，不允许 S02 读取 users 表。
- S02 仅管理商品、结算批次、订单、订单项、评价、退款申请、库存流水、订单事件、集成待办与幂等记录。首次拆单与库存预留在一个农资本地事务中完成。
- S03 仅管理支付、退款执行、通道事件、集成待办与幂等记录。通道成功事实由 S03 负责，订单与库存修改仍由 S02 完成。
- 内部命令和事件按调用方及业务号去重，采用持久化投递、单调版本、接收去重与周期核对恢复；远程调用不持有数据库长事务，不使用跨服务外键或共享事务。

## 5. 明确不增加的服务

购物车是前端状态，不是第四个服务；商品、库存、订单、物流、评价、退款审批属于农资买卖服务内部模块。商家入驻属于用户管理服务，退款资金执行属于支付服务。农机共享、真实资金分账、退款后退货物流和独立通知服务不纳入本期。
