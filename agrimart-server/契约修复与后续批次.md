# 契约修复与后续批次

依据：[API 设计](./05-API设计-副本.md)。接口存在、文档可生成与业务契约完成分别验收。当前三个业务服务有 19 个 HTTP 操作，其中 `/users/health` 是辅助接口，匹配 54 个目标操作中的 18 个；这些操作也仍有字段及业务规则差距。

## 第一批：现有链路修复

- 支付内部查询、关单先校验 `X-Service-Token`，无效凭据返回 401，业务代码不执行。支付同步接口同时补齐身份及买家归属校验，他人记录返回 404。
- 网关按 HTTP 方法和明确路径放行注册、登录、公开商品查询、公开商品评价查询，以及两种 POST 供应商回调。放行未来路径不代表下游操作已经实现；缺少控制器时仍返回 404。
- 回调转发保留原始请求体、媒体类型及供应商签名头。客户端提交的内部服务凭据、网关身份头会被清除，受保护操作的身份只能来自认证服务。`/api/internal/**` 始终拒绝公开转发。
- 网关构造错误体不再因 null 值触发异常；下游 403、404、409 等状态和响应体原样返回。认证服务返回 401 时返回用户认证失败，认证依赖的 HTTP 故障返回 503。用户服务仍需 Bearer 令牌的接口由网关继续转发该令牌。
- 用户、交易、支付服务使用 common 的 `RequestAuth` 处理服务凭据、可信用户标识和认证错误分类。删除原 `ServiceAuth`、`GatewayIdentity` 及支付控制器中的独立校验逻辑。无效凭据为 401，`FORBIDDEN` / `MERCHANT_NOT_APPROVED` 为 403，资源缺失为 404，参数错误为 400，未预期异常为 500 且不暴露详情。
- 现有商品列表使用数据库分页，`page=1`、`size=10`，限制 `page<=1000000`、`size<=100`。响应变为 `data.records/total/page/size/totalPages`，按 `createdAt DESC, id DESC` 排序。新增 V2 迁移补充创建时间和索引，不修改 V1；旧商品时间补为迁移执行时刻，不能恢复历史真实创建时间。
- Swagger UI 与网关共用游客操作判定，避免页面要求游客接口填写令牌。

这一批只修现有链路，不增加退款、评价、入驻或供应商回调的业务实现。商品响应仍未完全达到 ProductVo；经营资格、平台禁售、分类和关键词筛选留在商品批次。内部凭据目前仍是共享令牌校验，按调用方和操作授权的服务身份体系尚未实现。

## 后续批次与验收边界

| 批次 | 契约范围 | 主要工作与完成条件 |
| --- | --- | --- |
| 商品补全 | S02-E01 至 E11 | 商品 DTO、详情与管理接口、筛选、经营资格及平台禁售；按角色和资源归属验证读写边界。入驻流程尚未完成时不能伪造经营资格已通过。 |
| 订单 | S02-E12 至 E20、T01/T02 | 结算批次及拆单、买卖双方列表、发货收货；服务端金额快照、库存事务与可信支付状态协作。 |
| 支付通道与回调 | S03-E01 至 E05、P01/P03 | 先确定真实沙箱供应商和签名协议，再实现原始请求验签、金额及关联校验、事件去重和通道应答；验签或持久化失败绝不确认成功。 |
| 退款 | S02-E21 至 E26、T03/T04、P02/P04 | 申请与审核、可信退款授权、执行和补偿；重复通知和重试不能重复退款或重复释放库存。依赖支付供应商适配完成。 |
| 评价 | S02-E27 至 E31 | 仅允许本人已完成订单项评价，永久唯一约束，公开与本人分页、商家回复权限。 |
| 入驻审批 | S01-E05 至 E08、U02 | 申请状态机、管理员审批与审计、经营资格生效和撤销；与商品经营权限一起联调。若先上线商品经营功能，该批次需要前置。 |

`Idempotency-Key` 尚未实现，不能仅靠“先查询再插入”宣称支持幂等。在各业务写接口批次中落实：持久化主体/操作/资源/键、规范化请求摘要和原响应；同键同请求重放原结果、同键不同请求返回 409；并发时通过唯一约束及本地事务保证原子性，至少保留 7 天。订单、支付及退款的永久业务唯一约束独立保留。

内部命令的 `commandId`、事实的 `eventId` 去重、版本校验、事务待办与补偿也必须随对应业务批次实现。统一鉴权工具不等同于完成调用方范围授权、商家审批、资金可信校验或整个业务状态机。

## 本批验证

- `mvn clean verify`：202 个测试通过，失败、错误和跳过均为 0，四个应用 JAR 重新生成。覆盖凭据缺失与错误、支付资源归属、HTTP 错误映射、游客白名单边界、回调原始内容转发、下游错误透传、Swagger 文档以及分页查询。
- 独立临时 MySQL 8.4 实例：执行交易服务 V1、插入旧商品，再执行 V2；确认商品保留、`created_at` 回填及组合索引成功。验证未使用开发数据卷，临时容器已清理。
- 未将供应商回调、实际退款或跨服务完整交易作为已验证功能。分页自动化测试使用 H2；MySQL 检查验证实际 DDL 和旧数据迁移，不等同于真实供应商或生产部署验收。
